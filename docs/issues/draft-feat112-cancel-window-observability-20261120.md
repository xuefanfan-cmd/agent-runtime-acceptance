# FEAT-112：取消请求到达瞬间的探针窗口不可观测，“实际落定”语义待确认（特性不可观测 + 裁决点）

日期：2026-11-20
性质：特性不可观测 Issue，附一个需特性设计裁决的语义问题；接收方 solution/DA 开发 + 特性设计。
草稿（checklist I-M7）。来源：`feat112/issues-unobservable-20261117.md` Issue 4，按模板补齐并在新基线复核。

## 结论摘要

§5.1.6 第 279 行要求“取消等无结论结果在**实际落定后**才释放探针名额”（验收出口 14）。控制面取消在一次同步 `/cancel` 调用内部完成认领确认、落定、发终态事实、释放名额，中间态对外无任何观测点；因此“落定**之前**名额未被释放”这半句只能验证到调用级粒度（E7 已验：落定后名额释放、保持 HALF_OPEN、下一任务可成为探针）。另请特性设计确认“实际落定”的指称。

## 场景说明与影响面

HALF_OPEN 下探针在途，用户取消该任务。特性档要求名额在取消“实际落定”后才释放——防止取消请求一到达就空出名额、放进第二个探针。当前这个“到达~落定”窗口在一次同步调用内，外部观测不到窗口内的名额状态。影响：E7 覆盖登记为“部分承接”（瞬间部分不可观测，已按口径挂本 Issue）；不阻塞其余判定。

## 三面核查（Pre-flight 三问）

1. 对外契约：`/cancel` 是同步调用，返回时窗口已结束；`/v1/health/detail` 无法在窗口内采样（窗口 < 一次 HTTP 往返）。
2. 日志：取消路径无窗口内日志；`cancel-drain-delay-ms` 只延迟**事实发出之后**的清理续跑，帮不上窗口本身（代码定位见下）。
3. 数据：无落库。

## 代码层定位（solution `96c23d4ea`，静态走读）

`common/agents/deepanalyze-java/engine/.../da/compat/TerminalClosure.java` `settleCancelledFromControlPlane`：`synchronized(record)` 块内完成认领收口、`landTerminalPair`（落定）、随后 `runClosureTail` 发终态事实（门在 `onTerminalFact` 的无结论分支释放名额）。全程一次调用栈，无可插观测/延迟点（`cancel-drain-delay-ms` 作用于 `submitCancelDrain`，在事实发出之后）。

## 裁决点（请特性设计确认）

`/cancel` 返回后，被取消任务的 core 轮次可能仍在后台清理（drain），而名额已释放。“实际落定”指**控制面落定终态**（当前实现），还是**执行真正停止**？两种读法下“落定后释放”的验收判据不同。E7 当前按前者判定。

特性档 `05af9cc3` §5.1.6 第 279 行、验收出口 14。2026-11-17 登记草稿；本轮 Linux 实跑 E7 承接部分 PASS（`linux-rest-1`），瞬间部分维持不可观测。

## 复现、反问与验收

- 复现：无法构造正向复现（这正是问题）；可验证的外围为 `Feat112ProbeTest#probeCancellationReleasesSlot`（E7，PASS）。
- 反问“窗口极短，有必要观测吗”：按特性档该窗口承载一条 MUST 语义（先落定后释放）；或提供观测/注入点，或由特性设计确认该语义以调用级粒度验收即可——二者选一都能闭环，现状是两头都没有。
- 验收：若提供仅测试 profile 的落定延迟注入点（同 `cancel-drain-delay-ms` 做法），E7 补窗口内断言转全承接；若裁定调用级粒度即可，覆盖登记去掉“部分承接”并在 testplan E7 行注明。
