# FEAT-112 特性不可观测 Issue 清单（2026-11-17，草稿，未提交）

口径：测试仓只做 SIT。下列要求按“对外契约 → 进程日志 → 持久化数据（Redis/数据库）”依次查找观测点，均不可观测或不可构造，故登记为 Issue，请开发或特性设计给出观测点（或确认该要求不需要 SIT 验收）。

代码基线：solution `origin/common`（`b4995983b`）、core `e24bcb74d`；特性档 `05af9cc3`；DA L2 以 PR 538 `3b1283ef` 为参考。

## Issue 1：降级门内部事件没有日志，终态事实日志缺终态时刻

- 特性条款：§5.1.2（窗口按终态时刻统计）、§5.1.4（过期事实豁免）、§3.2（部署监控门状态）、验收出口 4、15。
- 已查：
  - 对外契约：`/v1/health/detail` 只给 `state`、计数、比例、`probeInFlight`、`retryAfterSeconds`、`instanceId`，不含窗口边界、终态时刻。
  - 日志：门的 CLOSED→OPEN、OPEN→HALF_OPEN、HALF_OPEN→CLOSED、探针认领与释放、过期事实均无日志（ext `DegradationGate` 只有两条 DEBUG）；逐任务的 `terminal fact taskId= class= code=` 是 DEBUG，且不带终态时刻。
  - 数据：门状态与终态事实只在内存，不落 Redis 或数据库。
- 影响：B6、B7、E9 只能经时钟回拨间接构造，激活证明（某条事实确实乱序、确实过期）只能靠推算；部署侧无法从日志还原状态迁移。
- 建议：状态迁移打 INFO（含 instanceId、前后状态、触发原因）；终态事实日志带 `terminalAt` 与分类；过期事实单独一条日志。

## Issue 2：`prepare_failed` 外部不可构造

- 特性条款：§5.1.3 第 254 行（存储、编排等基础设施异常计分子）；DA L2（PR 538）§1.4 目标：建档后的意外故障计基础设施异常。
- 已查：`prepareAdmittedExecution` 在登记任务之后到提交执行池之前的步骤（事件缓冲绑定、翻译器与执行体构造）全在内存，只有 Error/OOM 能走到 `settleAdmissionFailure`；没有外部依赖可停。
- 影响：该分类无法在 SIT 验收；目前代码归 NOT_ADMITTED，与 DA L2 目标不一致也无法从外部发现。
- 建议：说明可触发的真实条件，或提供仅测试 profile 可用的故障注入点（同 `cancel-drain-delay-ms` 的做法）。

## Issue 3：故障代际值不可观测

- 特性条款：能力表“故障代际防假恢复”、§5.1.4、验收出口 11、15。
- 已查：诊断面与日志都没有代际值。
- 影响：C4 的“递增代际”只能经外部效果（迟到的探针成功不得 CLOSED，C5、C8）验证。效果已可验，本条为可选。
- 建议：如需直接观测，在诊断面或状态迁移日志中给出代际。

## Issue 4：取消请求到达瞬间的探针窗口不可观测

- 特性条款：§5.1.6 第 279 行（取消等无结论结果实际落定后才释放名额）、验收出口 14。
- 已查：控制面取消在一次同步 `/cancel` 调用内完成认领、落定、发事实、释放名额，外部看不到中间态；无日志；`cancel-drain-delay-ms` 只延迟事实发出之后的清理续跑，帮不上这个窗口。
- 另需确认：`/cancel` 返回后，被取消任务的 core 轮次可能仍在后台清理（drain），此时名额已释放。请特性设计确认“实际落定”指控制面落定终态，还是执行真正停止。
- 影响：E7 只验“落定后释放、保持 HALF_OPEN、下一任务可成为探针”。
