## 2. 当前执行判定

整体链路为 **dependency-gated**，必须同时满足：

1. 正式 `agent-client` 产品制品可被业务测试引用；不能使用 acceptance helper 或 L2 fake。
2. 正式 Gateway 提供统一 facade、DIRECT/BUS path-mode、RDC 接线和测试凭证。
3. FEAT-017 runtime consumer/response producer 已交付，BUS 能真正到达外部 Agent JAR。
4. 三个 demo JAR 提供 FEAT-014 BUS transport profile；当前配置 URL 直连不能替代。
5. runtime 对 `metadata.clientTools` 的端侧工具请求/续接公开合同可用。
6. RDC、Event Bus 和 broker 有可执行制品与受控测试环境。
7. Gateway/runtime 已提供文档化的逻辑目标到 RDC 查询接线；测试不通过未定义配置项手工注入 routeHandle。

缺任一条件时，只能运行对应单特性已具备的局部用例，不能宣称整体链路通过，也不能用 mock runtime、临时 Gateway 测具或直接 A2A 请求补齐缺口。

## 3. 统一 Fixture 与观测点

- 按 PostgreSQL/RDC -> broker/Event Bus -> hotel -> trip -> mainplan -> Gateway -> client 的依赖顺序启动；就绪检查只作前置，不单列特性用例。
- RDC 中按同一 tenant 注册 mainplan/trip/hotel 的已知 agentId；业务调用只提交逻辑 agentId，由 Gateway/runtime 的正式 RDC 接线自行查询和消费 handle。测试以同一 correlation 的 RDC 公开查询审计和目标实例请求审计共同证明 FEAT-016 被真实调用；测试侧预查询或 endpoint 命中任一单独证据不足以通过。client/Agent 永不见 routeHandle、endpoint 或实例 canary。
- client 注册 `travel.policy.read` Observation 工具；invocation 级显式暴露。返回唯一 policy canary，handler 有执行计数。
- 三个 Agent 使用测试侧可控的外部 LLM endpoint，以请求标记稳定产生端侧工具请求、mainplan->trip 与 trip->hotel 委托；Agent/runtime 仍为真实外部 JAR，禁止直接构造工具意图或远端成功响应代替执行。
- 三层证据同时成立才通过：
  - 业务层：client invocation/ToolExecutionRecord/最终行程；
  - 路由层：RDC 查询与目标 endpoint 请求审计；
  - 事件层：公开订阅端观察 FEAT-013/014 事件类型、tenant/correlation/taskId/载荷摘要。
- 日志只读本次 offset；token、Bearer、endpoint 与 payload 正文不写入失败报告。

## 5. 详细用例

### FEAT-E2E.bus.client-tool-two-hop - BUS 下端侧工具与两跳 Agent 闭环

- **状态/优先级**：dependency-gated, P0；**自动化状态**：design-only。
- **Story/来源**：七份 Feature 的当前交付交集及对应 L2；不承担各单特性 deferred 矩阵。
- **测试类型**：fixture-e2e。
- **Oracle 来源**：FEAT-006 的 client 语义、007 的本地工具、012/013 的 BUS 入口与事件、014 的 A2A 事件、016 的真实已知目标查询和拓扑透明。
- **G**：
  - Gateway `path-mode=BUS`，client 只配置 Gateway；
  - `travel.policy.read` 已注册，conversation 策略允许，invocation 策略明确暴露；
  - 三 Agent 以 BUS transport 启动；Gateway/runtime 只接收逻辑目标并经正式 RDC 接线自行查询，测试记录本次 correlation 对应的 RDC 查询审计；
  - 请求文本明确要求先读取客户端差标，再规划北京行程并查询酒店。
- **W**：业务通过 FEAT-006 `STREAMING invoke` 发起调用；真实 mainplan 请求端侧工具；client 执行并以 continuation 返回 policy canary；mainplan 随后委托 trip，trip 委托 hotel；业务消费至 COMPLETED。
- **T（按链路顺序）**：

| 观察点 | 必须成立 |
|---|---|
| FEAT-006 | 回显 conversationId/invocationRef/mode；事件含 Accepted、InputRequired(client tool)、Status/Content、Completed；业务不用 taskId |
| FEAT-007 | 本次 ToolView 只含已暴露工具；handler 执行一次；结果形成一次 continuation，最终文本引用 policy canary |
| FEAT-012 | 创建与 continuation 都经 BUS；输入等待由 FEAT-012/017 的 INVOCATION_INPUT_REQUIRED 投影，投影各只折叠一次；client 不见 correlation/route/topic；实时流由点对点 SSE 提供 |
| FEAT-013 | 存在同 tenant 的 CLIENT_INVOCATION_REQUESTED、ACCEPTED、RESPONSE/TERMINAL；Bus 无 token/SSE frame |
| FEAT-014 | 存在 mainplan->trip、trip->hotel 两组独立 A2A_CALL_REQUESTED/ACCEPTED/RESPONSE 或 TERMINAL；各自 remote taskId 不混用 |
| FEAT-016 | 本次 correlation 下 Gateway/runtime 对三个已知目标执行 by-agentId 查询并消费 opaque handle，且命中对应实例；client/Agent 侧无 endpoint/instance/routeHandle |
| 业务结果 | 最终行程同时包含客户端差标 canary 和 hotel mock 中的真实候选，证明前后两类工具结果进入同一业务闭环 |

- **不应断言**：固定自然语言、固定 token/状态轮数、内部 TaskStore/outbox/RDC SQL、Agent 编排算法。
- **失败归类**：任一链路证据或最终业务 canary 缺失为 Failure；§2 任一正式依赖缺失为 Skipped；测试环境/观察器异常为 Error。

### FEAT-E2E.path-parity-and-failure-boundary - DIRECT/BUS 等价与故障边界

- **状态/优先级**：dependency-gated, P0；**自动化状态**：partially automated；当前实现成功路径、BUS 公开事件与 DIRECT/BUS 无候选失败，broker 故障注入和 tenant-B 凭证分支仍为 design-only。
- **Story/来源**：FEAT-006/011/012/013/016 当前交付交集及对应 L2。
- **测试类型**：fixture-e2e。
- **Oracle 来源**：FEAT-006 的 facade 稳定语义、011/012 的路径差量、013 的 BUS 事件、016 的已知目标查询和租户隔离。
- **G**：固定同一 client facade、凭证、agentId、业务输入和断言；准备两个隔离 conversation；Gateway 可只通过配置在 DIRECT/BUS 间切换。事件和 Agent 请求审计清零。
- **W**：
  1. DIRECT 执行完整 streaming 差旅调用；
  2. 重启/切换 Gateway 为 BUS，以新 conversation 执行同一调用；
  3. 分别在 DIRECT 下使 RDC 无候选、BUS 下使 broker 不可用；
  4. 在 Gateway A2A 协议边界用 tenant-B 凭证发起 tenant-A 目标调用并续接 tenant-A taskId；直接调用 RDC resolve 的 forwarding contract 留在 FEAT-016 单特性方案，不插入 E2E 用户链路。
- **T**：

| 观察点 | 必须成立 |
|---|---|
| FEAT-006 | 两阶段对 client 的 invocation、事件和业务终态语义等价，业务代码与调用 facade 不变 |
| FEAT-011 | DIRECT 只走 Gateway->runtime HTTP/SSE，不产生 CLIENT_INVOCATION 事件；无候选返回 route 类确定错误且不触达 Agent |
| FEAT-012/013 | BUS 产生 FEAT-013 事件而不走 DIRECT 主路径；broker produce 不可用返回明确 enqueue/bus 路径错误，不能伪造成 route_not_found、已入队或成功 Task |
| FEAT-016 | 两阶段均出现与调用 correlation 对齐的已知 agentId 查询；tenant-B 不得命中或复用 tenant-A 路由，Gateway 对 tenant-B 续接 tenant-A taskId 同样拒绝，错误不泄漏目标存在性 |
| 路径边界 | 两种响应均不泄漏实际路径；测试不检查 Gateway 等待窗口、缓存或任何内部表 |
- **不应断言**：DIRECT/BUS 时延相等、自然语言逐字相等、内部 path/cache/routeHandle 结构。
- **失败归类**：client 语义漂移、错误层级混淆、跨租户成功或链路证据缺失为 Failure；正式依赖缺失为 Skipped；切换/环境异常为 Error。
- **方法**：`featE2eDirectAndBusPathsPreserveClientSemanticsAndFailureBoundaries()`。
- **标签**：`@Tag("fixture-e2e")`、`@Story("FEAT-E2E.path-parity-and-failure-boundary: DIRECT/BUS 等价与故障边界")`、`@Tag("story-feat-e2e-path-parity-and-failure-boundary")`，并加方法级 `@Tag("feat-006")`、`@Tag("feat-011")`、`@Tag("feat-012")`、`@Tag("feat-013")`、`@Tag("feat-016")`。
- **DisplayName**：`Feat-E2E DIRECT 与 BUS 切换保持客户端语义并正确区分路由和总线故障`。

执行基线：JDK 21；PowerShell 使用 `.\mvnw.cmd`，WSL/Git Bash 使用 `./mvnw`；默认 Maven 仓库 `~/.m2/repository`；Docker 提供 PostgreSQL、broker、Toxiproxy 和所需 backing services。travel/RDC 坐标见 §1.1。正式 agent-client、Gateway、Event Bus、FEAT-017 和 FEAT-014 BUS profile 的坐标/classifier、构建 SHA、服务别名与配置必须在执行前补齐；当前 `application-openjiuwen.yml` 尚未声明这些完整组件，因此两例均保持门禁。

```powershell

.\mvnw.cmd -Dtest.env=openjiuwen -Dit.test=ClientGatewayBusA2aRouteEndToEndIT verify

# 按 feature 选中单特性 Test 与整体 IT 中相关方法
.\mvnw.cmd -Dtest.env=openjiuwen -Dgroups=feat-014 verify

.\mvnw.cmd -Dtest.env=openjiuwen -Dgroups=story-feat-e2e-bus-client-tool-two-hop verify
```

整体测试同时带各 feature tag 和独立 story tag。单特性测试负责精确故障矩阵，整体测试只保留两条高价值跨层旅程。测试数据、确定性 LLM、payload 和 canary 由版本化资源自动准备；测试结束按 client -> Gateway -> Agent -> Event Bus/broker -> RDC/PostgreSQL 的逆依赖顺序关闭，恢复故障链路，清理容器、消息、临时目录和端口。

退出标准：已自动化的路径等价旅程必须以正式 Client、Gateway、RDC、Event Bus 和 caller/callee Runtime 制品穿透目标链路，每个被声明覆盖的 FEAT 都有独立外部证据。七特性 client-tool 两跳旅程仍须在正式组合 fixture 交付后实现并通过，届时才能宣称七特性整体链路通过；不存在 mock runtime、临时 Gateway、手工成功事件、直接 A2A 或 RDC resolve 补链；任一门禁未满足时只报告 Skipped。
