# 任务异常率降级门（准入熔断，不做请求级 fallback 链）

> **排期说明**：scope=v1130，正式编号为 FEAT-112。
>
> **L2 边界声明**：本文用业务语言描述模块的外部可观察行为，不规定内部类、函数或线程模型；实现级细节归属下游 L2 设计文档。配置项名、端点路径、错误码和跨模块契约名可以保留。
>
> **测试章节说明**：本特性不合入 core 主仓，按既定规矩不附 UT/ST/测试矩阵三章；测试要求以 §2 验收出口与 §6 约束表达。

## 1. 特性定位

FEAT-112 定义 deepanalyze-java 的任务级异常自动降级能力：实例在滑动窗口内的任务系统异常率达到阈值后暂停接收新任务；静默期后进入半开，只放行一个真实任务探测执行链；探测证明恢复健康后才重新全面接收任务。

DA 原版的相应思想是“错误风暴时拒新、稍后探测、自愈”，但旧机制按异常次数计数，且可随时间直接清除降级。本特性采用**任务异常率 + 最小样本量 + 真实探测成功才恢复**，不把旧算法原样照搬；新进程首次初始化不属于旧实例恢复，例外边界见§5.1.7。

现有并发准入、执行池饱和拒绝和模型调用熔断均不替代本特性：前两者限制容量，后者保护单次模型调用；本特性保护实例的任务准入面。机制先在 agent-runtime-ext-java 自控，deepanalyze-java 的 `/run` 与 `/run-stream` 入口及健康诊断面必须完成消费接线。

### 术语约定

| 术语 | 定义 |
|---|---|
| 有效终态任务 | 已被实例受理并到达可评价终态的逻辑任务；取消、准入拒绝等无结论结果按 §5 排除 |
| 系统异常 | 共享模型、网络、编排、存储或工具基础设施异常导致的最终任务失败，不含预期业务失败和用户主动行为 |
| 异常率 | 窗口内计入系统异常的任务数除以有效终态任务数 |
| OPEN | 降级态，拒收全部新任务，在途任务和观察/控制入口继续 |
| HALF_OPEN | 半开态，每实例只允许一个真实新任务作为恢复探针，其余新任务仍拒收 |
| CLOSED | 正常态，按常规容量规则接收新任务 |
| 真实探针 | 经正常新任务入口受理、真实经过执行链的任务；不包括内部合成成功或仅做健康检查 |
| 故障代际 | 每次计入类系统异常递增的实例本地版本；探针认领时记录，用于阻止迟到成功覆盖新故障 |
| 过期事实 | 到达降级门时，终态时刻已不在单调窗口水位对应的 `(windowAnchor-window, windowAnchor]` 内；下界相等也视为过期 |

### 1.1 方案选择记录

| 候选 | 结论 | 理由 |
|---|---|---|
| 滑动窗口异常率 + 最小样本 + 单真实任务半开 + 故障代际 | **采纳** | 避免小样本误判和错误风暴；时间到只半开，任何旧任务或探针的新故障都能否决迟到恢复 |
| 沿用原版固定异常次数 + 时间到自动恢复 | 否决 | 不同流量下阈值含义不一致；旧故障过期不等于执行链恢复 |
| 直接复用模型熔断器拒收任务 | 否决 | 模型熔断不表达任务级准入、在途任务和业务失败边界 |
| 内部定时合成任务探测 | 否决 | 增加成本和假业务语义，难以覆盖真实请求路径 |

### 1.2 本期承接边界

- agent-runtime-ext-java 提供实例级降级门机制和统一结构化任务终态分类；deepanalyze-java 负责双入口、分类事实传递和健康诊断接线，不另建分类口径。
- **终态分类归属裁决**：agent-runtime-ext-java 是唯一结构化任务终态分类与唯一记账点；FEAT-111 的失败反思和本篇窗口统计消费同一分类结果，不得在 API 规范或宿主文案层另建第二套分类。分类枚举、结构化字段、载体与生命周期由该模块的独立 L2 规格定义，并须无损覆盖 §5.1.3 的验收矩阵。稳定错误码 181012 只引用 FEAT-054 已登记的上下文过长事实，不新建错误码注册表。
- **显式依赖**：FEAT-109 提供“护栏正常拦截/用户拒绝”的结构化事实，FEAT-110 提供 `/resume` 续跑入口；二者是分类矩阵和降级不阻断清单能够成立的前置。
- 本期只覆盖 `POST /api/agents/run` 与 `POST /api/agents/run-stream`。通用 runtime 其他入口待通用化后另行归入主仓。
- D4 负责前端提示与恢复提示消除；引擎提供带实例标识的即时 503 错误和可刷新诊断状态。

| 【新增特性】校验与准入顺序 | MUST | 双入口统一为入站认证及参数/媒体/team 校验→降级准入或探针认领→taskId/注册/start/提交；无效请求不占用探针 |
| 【新增特性】不制造假任务 | MUST | 降级拒收发生在 taskId 分配、任务注册、属主绑定、start 事件和执行提交之前；拒收请求不进入任务列表、缓冲或窗口 |

| 【新增特性】故障代际防假恢复 | MUST | HALF_OPEN 中任何已受理任务发生未过期的计入类系统异常，无论探针或旧任务，都立即回 OPEN 并重算静默期；探针只有在认领后的故障代际未变化时才可关门；过期事实按 §5.1.4 的明确豁免处理 |

| 其他 runtime 入口 | OUT | 本期不扩展到 `/v1/query`、WebFlux、标准 A2A、Agent Bus、custom-rest |

| 分桶降级 | OUT | 不按租户、会话、模型或 Agent 分桶；本期是实例级准入自保 |
**验收出口**（逐项可黑盒判定）：

1. ext 未显式开启时连续系统异常不产生降级拒收；DA 交付配置开启后诊断面 enabled=true；
2. 最小样本为 20 时，前 19 个有效任务全部为系统异常仍不因本门拒新；第 20 个有效任务完成记账后，后续新任务才被拒；
3. 窗口内 10 个系统异常与 30 个正常终态并存时异常率仅 25%，不得开门；20 个样本中 10 个系统异常时按默认阈值开门；
4. 使用缩短窗口验证旧样本过期；OPEN 中旧样本全部过期也不得自动 CLOSED；静默期后无真实新任务可长期 HALF_OPEN且不生成假探针；
5. 用户取消、入站 400、护栏正常拒绝、预期业务失败、具有结构化 181012 类别的上下文过长不增加系统异常分子；最终因模型 5xx、超时、重试耗尽 429、共享 401/403、配额或内部基础设施异常失败必须计入；非上下文过长的内容拒绝若只具有普通非重试/未知类别，按系统异常而非用户问题记账；模型 5xx 重试成功只计正常样本；拒收请求不改变分子或分母；上述终态记账以事实未过期为前提，过期事实按 §5.1.4 处理；
6. 断流后任务最终系统失败仍计分子和分母，断流后正常完成只计分母，重连不新增样本；慢消费者也不改变任务终态分类；
7. OPEN 后 `/run` 与 `/run-stream` 均返回 HTTP 503、`ENGINE_DEGRADED`、`degraded=true`、`retryable=true`、instanceId 和相同状态字段；OPEN 的标准 `Retry-After` 与 retryAfterSeconds 一致，HALF_OPEN 省略恢复时间；run-stream 不得得到 200 SSE 或 start/error/done 假任务流；
8. 拒收前后任务列表不增加记录、执行依赖未收到调用；OPEN 前已运行任务可继续完成，状态、重连、取消、注入和回答恢复仍按原契约工作；
9. 故障撤除并等待静默期后只转 HALF_OPEN，真实探测成功前不得 CLOSED，D4 提示不得消失；
10. HALF_OPEN 同时发起多个有效新任务，仅一个进入真实执行，其余返回 503 且 state=HALF_OPEN；
11. 半开探针继续发生未过期的系统异常时，该任务按真实失败契约返回，门回 OPEN 并重新等待完整静默期；过期落定只按 §5.1.4 释放当前探针名额；
12. 故障消除后半开真实任务正常完成，门转 CLOSED、窗口清空，后续双入口正常执行；无系统异常的预期业务失败同样可证明执行链健康并关门；
13. 半开探针到达 awaiting_answer 时转 CLOSED并释放名额但不记样本；后续回答续跑发生未过期系统异常时该逻辑任务只记一次分子和分母；inject、恢复、内部工具调用和子 Agent 均不得额外放大同一逻辑任务样本；
14. 半开任务在健康边界前被取消时，必须等取消实际落定才释放名额并保持 HALF_OPEN；取消请求到达的瞬间不得提前允许第二探针；
15. HALF_OPEN 中旧在途任务的未过期系统故障先于探针健康结果记账时，门必须回 OPEN，探针迟到成功不得 CLOSED；若 CLOSED 已先成立，后续故障按正常 CLOSED 窗口记账；探针取消后旧任务的未过期故障同样回 OPEN；过期事实不改写状态或代际，当前探针的过期落定只释放名额并允许下一真实探针；
16. 启动空窗口、恢复后清窗口和禁用态的诊断响应均有确定字段：sampleCount/systemFailureCount/systemFailureRate=0、probeInFlight=false、status=healthy、state=CLOSED；CLOSED/OPEN/HALF_OPEN 均 HTTP 200且要求合法服务间认证；仅门状态变化时 `/health` 不变、`/ready` 不新增 down，诊断面不泄露原始异常、用户输入、工具参数或密钥；
17. 两实例注入不同故障历史时可分别 OPEN 与 CLOSED，半开名额互不影响；A 的 503 与诊断均带 A 的 instanceId，不得用 B 的 CLOSED 清除 A 的 D4 提示；
18. OPEN 与 HALF_OPEN 下双入口的基本参数错误、媒体不存在、媒体白名单拒绝、team 不存在及 team 通道不可用均先返回既有校验错误而非 ENGINE_DEGRADED，且不占用探针；有效请求才进入降级准入；认领后并发/执行池拒绝按无结论释放名额；
19. `window<=0`、`min-sample-size=0`、阈值 `<=0`、`>1` 或 NaN、`open-quiet-period<0` 均启动失败并指出具体键名；`min-sample-size=1`、`failure-rate-threshold=1` 和 `open-quiet-period=0` 为合法边界。
20. 在OPEN状态重启进程后，新进程按§5.1.7初始化为CLOSED空窗口；该结果只能记为“新进程初始化”，不得记为旧实例经真实探针恢复。监控必须结合进程启动事件保留原故障上下文，不得仅凭重启清除故障告警或伪造健康探针记录。

## 3. 外部接口与入口要求

| 入口 | 类型 | 事实要求 |
|---|---|---|
| `/run`、`/run-stream` | 新任务HTTP入口 | 校验后共用实例级降级准入；拒收在任务建档和SSE建立前返回统一503 JSON |
| `/v1/health/detail` | 健康诊断端点 | 三态均返回200和实例级门状态，纳入服务间认证，不返回原始异常或配置秘密 |
| `openjiuwen.service.degradation-gate` | YAML配置 | 提供开关、窗口、最小样本、阈值和静默期，非法值启动失败 |
| 状态、重连、取消、注入、回答与恢复入口 | 在途任务控制面 | 不受降级门阻断，继续按原契约处理已受理任务 |

### 3.1 新任务准入

覆盖：

- `POST /api/agents/run`
- `POST /api/agents/run-stream`

双入口处理顺序统一为：

```text
入站认证及参数/媒体/team 校验
  -> 降级门准入或半开探针认领
  -> taskId 分配、任务注册、属主绑定、start、执行提交
```

OPEN 或 HALF_OPEN 探针已被占用时，统一返回：

```json
{
  "error": "Agent is temporarily not accepting new tasks",
  "code": "ENGINE_DEGRADED",
  "degraded": true,
  "retryable": true,
  "state": "OPEN",
  "instanceId": "deepanalyze-agent-1",
  "retryAfterSeconds": 87
}
```

| 字段/行为 | 契约 |
|---|---|
| HTTP | 503；OPEN 时同时返回标准 `Retry-After`，与 retryAfterSeconds 使用相同的向上取整秒数 |
| `code` | 固定 `ENGINE_DEGRADED`，不复用 `ENGINE_BUSY` 或 `ENGINE_INTERNAL` |
| `state` / `instanceId` | OPEN 或 HALF_OPEN，以及实际拒收实例 |
| `retryAfterSeconds` | OPEN 时为距半开的剩余秒数；HALF_OPEN 探针在途时省略，不编造恢复时间 |
| run-stream | 必须在 SSE 建立前返回 JSON，不先回 200 再补错误事件 |
| 副作用 | 不创建 taskId、任务记录、start 事件或执行许可，不进入异常率窗口 |

以下入口不被降级门阻断：`/stream`、`/status`、`/task`、`/tasks`、`/cancel`、`/inject`、`/answer`、`/message`、`/resume`。

### 3.2 健康诊断面

新增 `GET /v1/health/detail`，纳入既有服务间认证，不像 `/ready` 一样豁免。三种状态均返回 HTTP 200：

```json
{
  "status": "degraded",
  "degradationGate": {
    "enabled": true,
    "state": "HALF_OPEN",
    "instanceId": "deepanalyze-agent-1",
    "sampleCount": 20,
    "systemFailureCount": 11,
    "systemFailureRate": 0.55,
    "probeInFlight": true
  }
}
```

- CLOSED 时 `status="healthy"`，OPEN/HALF_OPEN 时 `status="degraded"`。
- 空窗口时 sampleCount、systemFailureCount、systemFailureRate 均为 0，禁止 NaN；恢复后清窗口使用相同零值。
- 禁用时固定 `status="healthy"`、`enabled=false`、`state="CLOSED"`、零计数、probeInFlight=false。
- 不返回原始异常、用户输入、工具参数或供应商密钥。
- 既有 `/health` 不变；`/ready` 只表达原组件就绪语义，门状态本身不新增 down 分量。
- D4 在 OPEN 时提示暂停接收新任务，HALF_OPEN 时持续提示正在真实探测恢复，只有同一 instanceId 进入 CLOSED 才消除提示。
- 部署方必须监控 `degradationGate.state` 和 `probeInFlight`：OPEN 触发实例级故障告警，HALF_OPEN 持续超过部署 SLO 规定的恢复观察阈值时触发“无真实探针或恢复停滞”告警；阈值由部署流量与恢复目标确定，不在引擎内编造固定值，也不得用定时自动 CLOSED 消除告警。

### 3.3 配置面

```yaml
openjiuwen:
  service:
    degradation-gate:
      enabled: false
      window: 5m
      min-sample-size: 20
      failure-rate-threshold: 0.50
      open-quiet-period: 2m
```

| 配置 | 默认值 | 约束 |
|---|---|---|
| `enabled` | ext 为 false；DA 部署显式 true | 关闭时不产生降级门行为变化 |
| `window` | 5m | 大于 0 |
| `min-sample-size` | 20 | 大于等于 1 |
| `failure-rate-threshold` | 0.50 | 大于 0 且小于等于 1 |
| `open-quiet-period` | 2m | 大于等于 0 |
| 半开探针数 | 固定 1 | 本期不开放调大 |

非法配置在启动期明确报错并指出键名，不静默替换默认值。

## 4. 场景与用户旅程

| 场景 | 前置条件 | 用户/系统动作 | 期望行为 |
|---|---|---|---|
| 小样本故障 | 有效样本不足 20 | 连续系统异常 | 记录但不拒新，避免一次故障拖停实例 |
| 异常率超标 | 样本达到 20，异常率达到 50% | 新任务到达 | 转 OPEN，双入口 503，无假任务 |
| 重试成功 | 模型先 5xx，内部重试后任务成功 | 任务完成 | 只计正常样本，不把中间错误当最终失败 |
| 客户端断流 | 后台任务继续 | 任务后来成功或系统失败 | 传输事件不记账，最终按真实终态唯一分类 |
| 在途任务收尾 | 门已 OPEN，旧任务仍运行 | 查询、inject、回答或取消旧任务 | 旧任务和控制观察面继续，只有新任务被拦 |
| 静默期结束 | 最近系统故障已超 2 分钟 | 无新任务或诊断刷新 | 只转 HALF_OPEN，未证明恢复 |
| 半开并发竞争 | 门为 HALF_OPEN | 多个有效新任务同时到达 | 一个真实任务被认领，其余 503 |
| 探针待答 | 半开任务到达 awaiting_answer | 门恢复健康 | CLOSED、释放名额但不记样本；后续最终终态再唯一记账 |
| 探针业务失败 | 半开任务发生预期业务失败 | 任务终态 | 证明执行链可工作，可 CLOSED并计正常样本 |
| 旧任务故障竞争 | 半开探针在途，旧任务发生未过期系统失败 | 探针随后成功 | 旧故障先记账则回 OPEN，迟到成功不覆盖 |
| 探针取消 | 用户请求取消半开任务 | 等待取消实际落定 | 落定后才释放名额，保持 HALF_OPEN |
| 多实例部署 | 两实例故障历史不同 | 分别查询和发起任务 | 状态独立，D4 按 instanceId 关联提示 |

## 5. 行为语义与边界

### 5.1 核心行为语义

#### 5.1.1 新任务准入与分发语义

- 双入口先完成入站认证及参数、媒体、team校验，再执行降级准入或探针认领，最后才分配taskId、注册任务并提交执行。
- OPEN及HALF_OPEN探针已占用时，在任务建档和SSE建立前返回统一503 JSON；无效请求不占探针，拒收请求不进入任务列表或窗口。
- 降级只拦新增任务，状态、重连、取消、注入、回答和恢复等在途任务入口继续按原契约工作。

#### 5.1.2 窗口算法与故障代际

- 在任务终态时刻记账，统计 `(now-window, now]` 内的有效终态任务；已越过窗口下界的迟到事实按 §5.1.4 豁免。
- `systemFailureRate = countedSystemFailures / eligibleTerminalTasks`；空窗口对外为 0。
- 只有样本达到最小量且异常率达到阈值时 CLOSED 才转 OPEN。
- OPEN 期间旧样本过期不会自动 CLOSED；OPEN 前已放行任务若发生未过期系统异常，更新最近故障时间并递增故障代际。
- 探针认领时记录当前故障代际。HALF_OPEN 中任何已受理任务的未过期系统异常都递增代际并立即回 OPEN；只有探针健康结果线性化时代际仍等于认领值，才允许 CLOSED 和清窗口。
- 终态时刻、准入当前时间和诊断当前时间共同推进单调窗口水位。到达时已过期的事实不再进入窗口，不改变样本、故障代际、最近故障时间或门状态；若属于当前在途探针，必须只释放其名额并保持 HALF_OPEN，使后续真实任务可以重新探测。
- 过期豁免只处理越过窗口下界的迟到事实，不得用于忽略仍在窗口内的新系统异常，也不得把过期落定记为健康恢复。
- 若 CLOSED 先成立，其后故障按正常 CLOSED 窗口记账；不得用后来的故障追溯改写已完成的状态迁移。

#### 5.1.3 任务结果分类矩阵

| 最终结果类别 | 系统异常分子 | 有效样本分母 |
|---|---:|---:|
| 正常完成 | 否 | 是 |
| 预期业务失败、正常工具业务错误、无结果 | 否 | 是 |
| 具有结构化上下文过长类别（如稳定错误码 181012）的单任务输入失败 | 否 | 是 |
| 护栏正常拦截、用户拒绝危险操作 | 否 | 是 |
| 用户取消、护栏确认处取消 | 否 | 否 |
| 入站认证、参数、媒体等 4xx | 否 | 否 |
| 会话忙、并发满、执行池满、降级门自身拒收 | 否 | 否 |
| 任务最终因模型 5xx、网络、连接/流/任务超时、重试耗尽 429 失败 | 是 | 是 |
| 任务最终因共享 provider 401/403、余额或配额不足失败 | 是 | 是 |
| 任务最终因未预期编排、处理器、存储、工具基础设施异常失败 | 是 | 是 |

断流、慢消费者和 SSE 重连不属于该矩阵，因为它们不是任务终态。它们本身不生成样本，任务后续仍按真实终态分类。入站 4xx 与上游共享服务 4xx 必须分开。

“单任务输入问题”只承诺现有结构化事实能够明确识别的上下文过长类别；不承诺泛化识别所有“请求内容被模型拒绝”。没有该结构化类别的普通非重试或未知模型失败按系统异常记账，不得根据错误文案推定是用户内容问题。

唯一记账点必须保存结构化结果类别；同为 failed，预期业务失败只计分母，基础设施异常同时计分子和分母，不能根据展示文本重新猜测。

#### 5.1.4 故障代际与异步结果语义

- 探针认领时记录当前故障代际；HALF_OPEN中任何已受理任务的未过期系统异常都递增代际并立即回OPEN，旧任务故障不得被迟到探针成功覆盖。
- 过期事实不重新记账或否决探针；若它是当前探针的落定结果，只释放名额并保持HALF_OPEN，不递增代际、不改变最近故障时间，也不产生健康恢复结论。该豁免用于避免窗口外的迟到结果破坏既有状态或永久占用探针名额。
- 探针健康结果线性化时代际未变化才允许CLOSED；若CLOSED已先成立，后续故障按正常CLOSED窗口记账，不追溯改写已完成迁移。
- 除上述过期豁免外，每个逻辑任务只在最终终态记账一次，回答、恢复、inject、内部重试、工具和子Agent不各自放大样本。

#### 5.1.5 传输与SSE语义

- 断流、慢消费者和SSE重连不是任务终态，不生成独立样本；任务后续仍按真实终态分类。
- run-stream拒收必须在SSE建立前返回JSON，不得先返回200再补start/error/done假任务流。
- OPEN前已受理任务可继续产生正常事件流，降级不取消或改写其结果。

#### 5.1.6 半开阻塞与探针结果语义

- 静默期结束只允许OPEN→HALF_OPEN；每实例同时最多一个真实新任务探针，其余有效新任务继续503。
- 健康结果包括正常完成、无系统异常的预期业务失败和awaiting_answer；前两者到达终态时按健康样本记账，awaiting_answer不提前记样本。
- 探针就是普通真实用户任务，不免费重试、不改写结果，也不向调用方暴露其探针身份；取消或认领后资源拒绝必须等无结论结果实际落定才释放名额并保持HALF_OPEN。
- 当前探针的过期落定事实按独立的过期释放边界处理：只释放名额并保持HALF_OPEN，不记样本、不递增代际；下一真实新任务可重新成为探针。
- 无新流量时可长期HALF_OPEN，不合成内部探针或自动CLOSED。

#### 5.1.7 状态机与进程初始化语义

```text
CLOSED
  | 有效样本达到最小量，且系统异常率达到阈值
  v
OPEN
  | 自最近一次计入类系统故障起静默达到 open-quiet-period
  v
HALF_OPEN
  | 原子认领唯一真实任务探针并记录故障代际
  +-- 任意已受理任务的未过期系统异常 -> OPEN，递增代际并重新计时
  +-- 健康执行结果且代际未变 -> CLOSED，清空窗口
  +-- 无结论结果实际落定 -----> 保持 HALF_OPEN，释放探针名额
  +-- 当前探针过期落定 --------> 保持 HALF_OPEN，只释放探针名额
```

- 运行期从OPEN/HALF_OPEN转为CLOSED必须具有真实健康结果且故障代际未变化；旧样本过期、诊断查询和静默期结束均不构成健康证明。
- 进程首次启动从CLOSED、空窗口和初始故障代际开始，这是新进程初始化而非旧实例恢复，是上述规则的唯一例外；不持久化旧进程窗口和探针状态。
- 重启不得被记为真实探针恢复或通过恢复验收。监控必须结合进程启动事件保留原故障上下文，不得仅凭重启清除故障告警或伪造健康探针记录。

#### 5.1.8 诊断与多实例语义

- CLOSED时诊断status=healthy，OPEN/HALF_OPEN为degraded；空窗口和恢复后清窗口的样本、异常数及异常率均为0，禁止NaN。
- OPEN返回剩余静默秒数，HALF_OPEN省略retryAfterSeconds；诊断三态均HTTP200并纳入服务间认证。
- 窗口、探针和错误均按instanceId隔离；一个实例的CLOSED不得清除另一个实例的提示。`/health`不变，`/ready`不新增门状态down分量。

#### 5.1.9 错误、状态与可观测结果

| 场景 | 事实要求 |
|---|---|
| OPEN或HALF_OPEN探针已占用 | 503 `ENGINE_DEGRADED`，带state和instanceId；OPEN另带Retry-After，HALF_OPEN省略恢复时间 |
| 入站参数、媒体或team校验失败 | 返回既有校验错误，不占用探针、不创建任务、不进入窗口 |
| 探针或旧任务发生未过期系统异常 | 真实任务按原契约失败，门回OPEN并重算静默期，诊断可观察状态变化 |
| 当前探针发生过期落定 | 不记样本、不改变代际或最近故障时间；保持HALF_OPEN并只释放名额，允许下一真实探针 |
| 探针待答、业务失败或正常完成 | 按§5.1.6确定健康结果；待答不记样本，终态唯一记账 |
| 新进程启动 | CLOSED空窗口，诊断反映新进程状态；不得据此宣称旧实例已经真实探针恢复 |

### 5.2 显式边界与不承诺项

| 边界 | 当前版本不承诺 |
|---|---|
| 时间到自动恢复 | 只允许自动进入 HALF_OPEN；运行期CLOSED必须有真实健康结果且故障代际未变，新进程首次初始化除外 |
| 进程重启状态延续 | 不持久化旧窗口和探针；重启只是新进程CLOSED初始化，不算旧实例恢复或探针验收，不得仅凭重启清除告警 |
| 内部假探针 | 不合成模型调用、不伪造任务成功、不提供强制开关门测试端点 |
| 全 runtime 覆盖 | 只承诺 DA 双入口；通用化后另行扩展 |
| 集群一致性 | 不共享窗口、探针和状态，不提供集群恢复结论 |
| 展示文案分类 | 必须传递 agent-runtime-ext-java 的统一结构化结果事实，不从 error 文本反推 |
| 前端提示 | 展示与消除归 D4，引擎只保证错误和诊断状态一致 |

## 6. 对下游设计与实现的约束

- L2 必须在 agent-runtime-ext-java 给出任务终态到窗口样本的唯一分类与记账点，FEAT-111 消费同一结构化结果；稳定错误码 181012 直接引用 FEAT-054 既有上下文过长注册口径，横跨回答和续跑保留事实，不得新建注册表或重新解析展示文案。工具级 `permissionDecision=denied` 只能作为因果证据：只有最终失败确由正常护栏拦截或用户拒绝导致时才排除系统异常，任务随后正常完成或最终因其他系统异常失败时不得仅凭曾出现 denied 改写分类。
- L2 必须给出故障代际、故障记账和探针健康关门之间的原子先后关系，证明旧任务的未过期故障不会被迟到探针成功覆盖；同时落实 §5.1.4 的过期豁免，保证当前探针过期落定只释放名额，不把窗口外事实重新记账，也不造成 HALF_OPEN 永久占用。
- L2 必须证明双入口都在参数/媒体/team 校验之后、任务建档和 start 之前执行同一降级检查，并给出探针认领、无结论释放和状态迁移的并发设计。
- L2 必须明确 awaiting_answer 只释放探针不记样本，最终终态才唯一记账；断流和慢消费者不得被当作任务终态。
- DA 宿主双入口与诊断面必须消费同一实例状态；agent-runtime-ext-java 交付机制不等于完成 DA 接线。
- 合入时同步修订 FEAT-054 的服务面义务、《deepanalyze-java 对外 API 规范》的错误码与健康端点、D4 的提示语义：OPEN/HALF_OPEN 均持续提示，只有同一 instanceId 进入 CLOSED 才消除。
- L2必须明确新进程CLOSED初始化与运行期真实探针恢复的区别，监控不得仅凭重启清除原故障告警。
- 测试通过公开配置缩短窗口和静默期，通过故障注入制造真实任务结果；不得依赖强制开门、假探针或直接篡改内部状态。必须覆盖 §2 全部 20 项。
- 任何新增 DA 新任务入口、跨实例共享状态或自动 CLOSED 语义，必须先回本特性更新事实要求，再进入 L2 和实现。
