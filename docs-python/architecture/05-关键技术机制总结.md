# 关键横切机制

## 一、依赖倒置与契约检查

`domain` 只保存领域事实，`ports` 声明边界，`application` 组合用例，`adapters` 翻译外部世界，`bootstrap` 装配。`ports.contract.satisfies` 与 `bootstrap.contract_check.require` 共享判定逻辑，避免“能力位认为可用、装配期却放行错误对象”。

## 二、终答与完成信号

终答是 `QueryChunk` 内容帧，成功完成是 async iterator 正常结束。不能创造 `COMPLETED` chunk 来代替结束语义；REST 与 A2A 投影分别决定终答如何出现在 wire 上。

## 三、背压与有界等待

事件队列、`BoundedWaitingRegistry` 和排水窗口共同限制运行态增长。等待输入必须有明确 key、容量、清理时机和跨进程边界；无共享 TaskStore 时只能把它视为单进程降级。

## 四、错误先投影、再传播

远端和 adapter 可能先产出 error chunk，再继续抛出异常让入口推进 FAILED。吞掉异常会让调用方只看到一个看似正常结束的流，破坏终态判定。

## 五、兼容性分层

函数级验证锁定构造器，往返级验证锁定路由 / 状态码，流级验证锁定原始 SSE，真 socket 级验证锁定服务器与启动链路，差分级验证锁定存量兼容。任一层都不能替代其他层。
