# 三仓协作与扩展体系

> 本文档为 [OpenJiuwen 三仓技术架构总览](00-OpenJiuwen技术架构总览.md) 的子文档，分析三仓之间的扩展点矩阵、集成方式与端到端调用链。

---

## 一、扩展点矩阵

三仓之间通过四类扩展点协作：

| 扩展类型 | 定义位置 | 扩展位置 | 机制 |
|---------|---------|---------|------|
| Java SPI | agent-core-java | 任意（包括 agent-solution） | ServiceLoader 加载实现类 |
| AgentHandler SPI | agent-runtime-java spec | agent-solution runtime-ext | 实现 query/streamQuery 接口 |
| AgentRail | agent-core-java | agent-solution core-ext | agent.registerRail() 注册 |
| Spring Boot AutoConfiguration | agent-runtime-java | agent-solution runtime-ext | 条件装配 |

---

## 二、core-ext 与 core-java 的集成

`agent-core-ext-java` 直接依赖 `agent-core-java`，通过 Rail 机制扩展。扩展模块通过注册自定义 Rail 在 ReActAgent 循环的模型调用后钩子和工具异常钩子中插入逻辑，通过 forceFinish gate 短路 invoke 循环，实现验证→降级、重规划计数、根因诊断等控制流。

---

## 三、runtime-ext 与 runtime-java 的集成

`agent-runtime-ext-java` 的各适配器通过 AgentHandler SPI 和 Spring Boot 自动装配扩展 `agent-runtime-java`。agentcore-ext 继承基础 Handler 并通过 `installBeforeRun` 生命周期安装扩展能力；Versatile/AgentScope/CustomREST 适配器各自实现 AgentHandler 接口；bus-consumer 通过 event-bus SPI 端口接入事件总线。各模块提供条件自动装配，但通常只装配配置和安装器，不直接创建 Handler Bean，由宿主显式注册。

---

## 四、完整调用链（端到端）

以「客户端通过 Agent Bus 调用远端 Agent」为例，完整调用链贯穿三仓：

```
端侧 agent-client-sdk
  → A2A HTTP/SSE
    → agent-gateway (治理: 鉴权/租户/校验)
      → registry-discovery-center (路由解析)
        → event-bus-relay (两跳转发, 可靠投递)
          → agent-runtime-java (agent-service-app)
            → ServeOrchestrator
              → AgentCore ExtHandler (runtime-ext)
                → 安装远程 A2A 工具
                → agent-core-java Runner
                  → ReActAgent 执行
                    → Rail 链 (含 core-ext 的验证/重规划/降级)
                    → Model 调用
                    → Tool 调用 (含远程 A2A 委派中断)
                  → Checkpointer 状态保存
                → 响应回流
```
