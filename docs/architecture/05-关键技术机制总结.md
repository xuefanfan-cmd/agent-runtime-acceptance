# 关键技术机制总结

> 本文档为 [OpenJiuwen 三仓技术架构总览](00-OpenJiuwen技术架构总览.md) 的子文档，总结三仓中六个核心技术机制的设计要点。

---

## 一、Pregel 图执行模型

`agent-core-java` 的图执行引擎基于 Google Pregel 论文的 BSP 模型。每个 super-step 中所有活跃节点并行执行，步末通过 Channel 同步。这带来了三个工程优势：节点级并行、结构化状态持久化、中断恢复。Channel 机制支持屏障同步和触发式调度两种通信模式，路由策略支持条件路由、静态路由和屏障路由。

---

## 二、Checkpointer 生命周期

Checkpointer 是 Runner 与 Session 协作的核心纽带。Agent 完成后不自动清理状态（支持多轮对话延续），Workflow 正常完成后自动清理（图执行恢复用）。graph checkpoint 和 workflow state 分开存储。`conversation_id` 是贯穿 Session 创建、状态保存/恢复、多轮对话延续的核心纽带，四个独立命名空间通过 Key 格式隔离。

---

## 三、Rail 回调钩子链

Rail 机制是 Agent 执行过程中的回调钩子链，提供了模型调用后、工具异常时等钩子点。扩展模块通过注册自定义 Rail 在 ReActAgent 循环中插入验证、重规划、降级等逻辑。`forceFinish` gate 允许 Rail 短路 invoke 循环，是实现「验证→降级」控制流的基础。这一机制是 `agent-core-ext-java` 扩展能力的根基。

---

## 四、AgentHandler SPI 单向依赖

`agent-runtime-java` 的 spec 模块定义 AgentHandler 接口，所有执行后端（AgentCore、Versatile、AgentScope）都实现此接口。这保证了编排层（ServeOrchestrator）与执行后端的解耦——Controller 禁止绕过 Orchestrator 直连 Runner，所有请求经 Orchestrator 统一治理。

---

## 五、事件总线两跳转发

`agent-bus` 的 event-bus 采用两跳 broker 转发，内置治理（去重/租户/correlation/poison 守卫）和可靠投递（JDBC outbox/inbox + Flyway 迁移）。三角色互斥（caller/runtime/relay）避免了进程内耦合，gateway 与 RDC 和 runtime 全部通过 HTTP/SSE 端口通信。

---

## 六、自演进闭环

`agent-evolve` 实现了「数据采集 → 轨迹评估 → 策略优化 → 沙箱验证」的自演进闭环。evoagent-adapter 从 EDPAgent 日志增量采集结构化轨迹，evoagent 基于 ReflACT 管线执行优化，通过 managed-doc API 实现优化后 skill 文档的热更新。跨 operator 并行受单一 semaphore 控制，保证优化过程的可控性。
