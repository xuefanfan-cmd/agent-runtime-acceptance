## 遗漏（建议补进同一轮修改）

2026-11-16 用户口径：DA L2 的修改由评审员另开 PR 跟进；ext L2 不拆 PR，统一在 PR 463 跟进。据此，下文第 1 项只保留 ext L2 §2/§3，第 2 项只保留 §8 改写；已作为补充评论 200901772 发到 PR 463。

1. **规格 §2、§3 和 DA L2 §5.2 仍把建档前就返回的请求写成 NOT_ADMITTED。** 规格 §2 第 45 行 NOT_ADMITTED 的来源列着“入站认证/参数/媒体 4xx、……降级门自身拒收”，§3 第 63–64 行把这两类映射为 NOT_ADMITTED；DA L2 §5.2 第 333 行也列着“门自身拒收 → NOT_ADMITTED”。评论一.2 只改了 §4。如果 §2、§3 不同步，§3 的“无损映射自检”会前后矛盾。应写成：这些请求不产生事实、不计入，因此不经过任何分类。记账结论不变，只是文字。
2. **评审流程没有处理。** 规格放在标题为 FEAT-054“补交归档、无代码与行为变更”的 PR 中，PR 描述没有提到这份规格。按归档合入就跳过了需求侧评审。建议拆成单独 PR，或在 PR 描述中列为评审项。另外，规格 §8 仍请需求侧确认第 ② 问“一字不差”；按评论修改后这一问不再成立，§8 也要改写。
3. **core error 通道的覆盖范围。** 规格 §5 把它写作“模型重试耗尽等”。实际上运行中止（completion_timeout、core 侧中断的轮次）和达到最大迭代次数也走这条通道，DA 一律归为 MODEL_SERVICE_FAILURE。评论三.1 提到了最大迭代，但没有要求规格写明通道的覆盖范围。

1. ~~第二节涉及代码改动，规格不能先于代码宣称已实现……规格应写“目标 + 现状差距”。~~ **（2026-11-16 撤回，此条错误）** 规格是锚点，先于代码合入，写的就是目标行为；代码按规格修改，未落地的部分是实现缺陷，由实现侧跟踪，不需要规格降格为“现状描述”。据此发出的补充评论 200901772 已被用户删除。
